### 현행 4문항의 문제 3건

```
1 | 이 조직은 AI 활용 성과가 평가에 [어떻게 반영]되는지 명확히 설명한다
2 | 이 조직은 AI 활용 성과평가에 적용되는 [기준을 일관되게] 제시한다
3 | 이 조직은 AI 활용 여부가 성과평가에서 [어떻게 고려]되는지 명확한 절차를 제공한다
4 | 이 조직의 AI 활용 성과평가 절차는 구성원이 이해할 수 있도록 안내된다
```

| # | 문제 |
|---|---|
| 1 | **2번이 DV1과 「기준·일관」 어휘 공유** — 주어(조직 vs 절차)로만 갈려 H4 상호작용항 해석에 부담 |
| 2 | **1·3번의 「어떻게」** — MV에서는 금지 어휘. 층위 점검 필요 |
| 3 | 1·3번이 거의 같은 내용 → 과소대표 |

### ★ 선행 결정

**① 「AI 활용 성과평가」 표현이 연구 범위와 어긋난다**

```
✅ 본 연구 : AI와 협업해 만든 성과를 평가한다   (평가 대상에 AI가 개입)
❌ 다른 것 : AI를 활용해서 평가한다            (평가 주체가 AI)
```

**② 영역 구분 — ✅ 해소.** MOD는 **system 층위**로 확정됐다.

| 근거 | 내용 |
|---|---|
| Erdogan(2002) p.561 Proposition 1a | 평가기준 전달·기준 개발 참여 = **system** / 평가기간 중 피드백 = rater |
| Erdogan et al.(2001) p.217 Table 3 | `Knowing appraisal criteria` → system 절차공정성 **β=.27, p<.01** |
| 〃 p.213 | **단일 문항** — 평가 전에 어떤 기준으로 평가받을지 알고 있었는지 |

→ DV(단일 차원)와 층위가 어긋나지 않아 **H4 조절 논거가 강화된다.**

⚠️ **측정 방식 쟁점** — 현행 4문항은 *"조직이 …설명한다"*로 **조직 행위**를 묻는데 Erdogan et al.은 **응답자의 지식 상태**를 묻는다. 어느 쪽인지 결정 필요.
⚠️ Erdogan et al.의 문항은 **단일 문항**이라 그대로 쓸 수 없다(저자도 p.219에서 한계 인정). **계보 근거로만** 쓰고 문항은 별도 조달.

## 10. 작업 원칙

- **정의문 → 문항** 순서. 단 역방향도 있다(문항 확정 후 정의문 공백이 드러난 사례)
- 정의문·구성개념이 바뀌면 **전수 grep.** 범위에 `Analysis/`뿐 아니라 `Experiments/`·`Methodology/`·`Writing/`·`Zotero/` 포함
- **문항·정의문은 성준님이 작성.** Claude는 구조와 예문을 먼저 제시하고, 3축 좌표와 관문 6개로 검증
- **파일·절을 명시하지 않은 지적은 확인 대상이 아니다.** ⚠️ 위치는 **파일 → 절 제목 → 소제목/표 이름**으로 쓴다. **행 번호를 쓰지 않는다**(성준님이 셀 수 없고 편집하면 어긋난다). 행 번호는 파일 전달 시 `diff --stat` 예측에만 쓴다
- **확인한 것 / 추론한 것 / 미확인**을 구분한다. 원문을 보기 전 추론을 확정처럼 말하지 않는다
- **「측정되지 않은」** — 원전에 귀책을 두는 어휘를 쓰지 않는다
- **실무 기여를 배제하지 않는다.** 중심에 두지 않을 뿐이다
- **「첫 시도」·「최초」 금지.** 확보한 문헌 수를 넘는 일반화를 하지 않는다
- 시작 = `git pull` / 종료 = 반드시 `push` (미완이어도)
- ⚠️ 파일을 배치한 뒤 **`git --no-pager diff --stat`으로 예상 줄 수 확인.** 08-15에 같은 커밋이 두 번 올라가 A0-2 작업이 유실된 사례
- ⚠️ **파일 배치는 성준님이 직접 한다.** Claude는 **파일 + 리포 경로 표 + 예상 `diff --stat` + git 명령(`add`·`commit`·`push`)** 만 제공한다. `copy`·`mv` 등 파일을 옮기는 명령은 주지 않는다
- ⚠️ **두 기기에서 같은 배치를 하지 않는다.** 한 기기에서만 커밋하고 다른 기기는 `pull`로 받는다 (08-17 중복 커밋 사례)
- ⚠️ **frontmatter 값에 콜론을 넣지 않는다.** YAML 파싱이 깨진다
- ⚠️ 리포 폴더는 **`Zotero/`(대문자)** — macOS는 대소문자를 구분하지 않아 `mp`에서는 열리지만 `wp`에서 깨진다

### ★ action-items·review 운용 규칙 [08-17 신설]

| 종류 | 성격 | 규칙 |
|---|---|---|
| `action-items-*` | **휘발성** | 새 파일은 **자립**한다. 미결은 링크가 아니라 **본문 이관**. 이전 파일은 종료 표기 후 아카이브 |
| `review-*` | **시점 기록** | 누적. 수정하지 않음 |
| `Analysis/`·`Writing/` 등 | **영속** | 결론이 사는 곳 |

> **결론은 영속 파일로, 미결은 최신 action-items로.** action-items끼리 서로 참조해 사슬이 되면 안 된다.
