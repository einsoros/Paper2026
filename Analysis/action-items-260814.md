## ★ A. G1 — IV 신규 구성개념 방어 3단 논거 ⬜ **최우선**

- **Done =** 한 페이지 정리 → `Writing/proposal-draft-260813.md`에 삽입

### 왜 필요한가

**교수님 원칙** (김효현·김효양 면담 모두에서 반복)
> 임의로 변수를 구성하면 신뢰성을 인정받지 못하며, **통계적 절차에 의해 검증된 기존 학술 변수**를 활용해야 한다.

「성과 기여 귀속 모호성」은 기존 학술 변수가 아니다. **회피 불가능하며 면담에서 나올 가능성이 높다.**

### ⚠️ 먼저 구분할 것 — 이것이 방어의 핵

| | 지적 내용 |
|---|---|
| 김효현 숙달경험 | *"사실상 근무 경력에 가깝다"* → **기존 변수의 열등한 대체물** |
| 본 연구 귀속 모호성 | 기존 변수로 잡히지 않는 현상 → **신규 영역** |

전자는 *"있는 걸 왜 새로 만드나"*, 후자는 *"없는 걸 만들어도 되나"*. **답이 다르다.**

### 답변 3단 — 이 순서로

| # | 논거 | 재료 위치 |
|---|---|---|
| **①** | **왜 기존 변수로 안 되는가** | `construct-definition` §I·§II `What It Is Not` — 비교 개념 6개(역할 모호성·과업 모호성·책임 모호성·accountability·construct contamination·evaluability)와의 차별. 특히 **사전(ex-ante) vs 사후(ex-post)** |
| **②** | **척도 개발 절차를 밟았는가** | MacKenzie et al.(2011)·Heggestad et al.(2019): 정의 → 내용영역(D1/D2) → 문항 → 내용타당도 → **파일럿** → EFA/CFA·AVE·HTMT. **08-04~08-13 작업이 정확히 이것** |
| **③** | **이론적 뿌리가 있는가** | IV = Weiner(1985) 귀인이론 / MV = **Rizzo(1970) 정의 (1)** — 원전이 정의했으나 요인분석에서 탈락해 미측정으로 남은 구성요소(items 8·16·24·30, p.160·162) |

### ★ 먼저 말할 것 — 방어 범위를 좁힌다

> **완전한 신규는 IV 하나다.** DV(Colquitt 2001)·MOD(Erdogan 2002)는 기존 학술 변수이고, MV는 Rizzo(1970) 정의 (1)에 뿌리가 있다.

이 사실을 먼저 밝히면 논의가 IV 하나로 좁혀진다.

### 형식

`proposal-guide` §05 패턴대로 **경로마다 이론 배정**을 명시한 표 + 위 3단을 한 슬라이드로. Appendix에 `What It Is Not` 표 전문.

## 작업 원칙

- **정의문 → 문항** 순서. 단 역방향도 있다 (문항 확정 후 정의문 공백이 드러난 사례)
- **정의문·구성개념이 바뀌면 전수 grep.** 범위: `Analysis/`·`Experiments/`·`Methodology/`·`Writing/`
- **상위 문서가 하위에 요구를 걸 때는 하위 파일명을 명시**한다
- **「이 절의 전제」 블록** — 각 절이 자기 전제를 선언, 상세는 소관 절에만
- **「출처 있음 ≠ 절차 밟음」** — 인용 시 그 출처가 타당화 절차를 밟았는지 확인한다
- **「정합성 ≠ 타당성」** — 문서끼리 어긋나지 않는 것과 설계가 현실에서 작동하는 것은 다르다. Claude는 근거를 말할 때 **「우리 문서 기준」인지 「외부 검증 기준」인지 구분**한다
- **판별 점검법**: 한 어구가 다른 구성개념 문항에 그대로 들어가도 자연스러우면 그 어구는 이쪽 것이 아니다
- **사후 정당화 감지 시 즉시 중단하고 반대 논거를 요청**
- 정의문 3인칭·명사구 / 문항 1인칭·완결문 / 시나리오 본문 2인칭
- **미완이어도 push.** 항목 단위로 커밋. **커밋 전 `git status`로 대상 파일 확인**
- Claude는 **파일·절을 명시**할 것. 부재 주장은 문서 전체 확인 후. **근거 없이 편들지 말 것.** **약어는 풀어서 병기**
