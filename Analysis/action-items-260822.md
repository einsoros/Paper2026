## 🔴 3. `logic-architecture` 본문 재작성 — 방향 C

현재 파일에는 **사실 정정과 재작성 대기 배너만** 들어가 있다. 본문 서술은 미실시.

### 3-1. Layer 3(a)·(b) — H2를 규칙 층으로

```
평가 결과를 예측할 수 없다
  → 일관된 기준이 적용되고 있다고 판단할 근거가 없다   (consistency)
  → 정확한 정보로 판정되고 있다고 판단할 근거가 없다   (accuracy)
  → 절차공정성 지각 저하
```

| 할 일 | |
|---|---|
| **a** | UMT를 **메커니즘 이론**으로 재배치 — *왜 불확실한 사람이 절차 정보에 의존하게 되는가* |
| **b** | H2 논거를 **규칙 층**으로 세운다. 우리 DV 3문항이 그 규칙이므로 측정과 논리의 층이 일치한다 |
| **c** | 📌 **원문 근거 인용** — Hartmann §5 결론이 형식성의 저TU 효과를 **consistency 증가**로, 고TU 무효과를 **정확성 손실**로 해석한다 |
| **d** | 🔴 **한계 명시 — 필수.** 논리이며 실증이 아니다. §07 한계 절에 배치. Layer 4의 08-13 선례와 동일 처리 |

⚠️ **accuracy 취급 주의** — Layer 3 [V17]은 accuracy를 **DV에서 제외**했다(IV와 순환 위험). 위 도식에서 accuracy는 **MV→DV 논리의 경유지**로만 쓰고 **DV 문항으로 올리지 않는다.** 이 구분을 문장에서 흐리면 순환 지적이 들어온다.

### 3-2. 「핵심 문제의식」 문장 — 🔴 재작성 필요

현행은 *절차를 개선하는 방식만으로는 그 원인에 닿지 못한다*로 끝난다. **a경로 조절이 지지되면 「절차 개선이 원인 쪽에 부분적으로 닿는다」가 되어 방향이 어긋난다.** 미지지일 때 원 결론과 더 강하게 맞는다. → **양쪽 결과를 다 수용하는 문장으로 바꾼다.**

## 9. 작업 원칙 — 자립용 요약

### 연구 태도

1. **판단하지 않고 확인한다.** 확인한 것 / 추론한 것 / 미확인을 구분한다
2. **근거 위치는 파일 → 절 제목 → 소제목·표 이름.** 행 번호를 쓰지 않는다
3. **성준님 편을 들지 않는다.** 근거로만 말한다
4. **결론은 영속 파일(`Analysis/`·`Writing/`), 미결은 최신 action-items**
5. **문항·정의문은 성준님이 쓴다.** Claude는 구조와 예문을 먼저 낸다
6. 🆕 **새 용어·약어는 판정보다 먼저 설명한다.** 원문 대조 시 본문 앞에 용어표를 놓는다

### ★★ 최소 체격 3원칙

| # | |
|---|---|
| 1 | **조사 깊이 ≠ 서술 깊이.** 근거는 action-items에, 본문에는 판정만 |
| 2 | **파기 전에 묻는다 — 「이걸 확인하면 판정이 바뀌는가.」** 안 바뀌면 ⬜ 후속연구 |
| 3 | **방어 논거는 층을 늘려 강해지지 않는다.** 가장 강한 한 층만 본문에 |

⚠️ **「후속연구」와 「미확보」는 다르다.** 확인해도 판정이 안 바뀌어서 내리는 것이 후속연구이고, 리포에 없는 것은 미확보다. 08-18에 혼동한 사례가 있다.

### 파일 프로세스

- **배치는 성준님이 직접.** Claude는 파일 + 리포 경로 표 + 예상 `diff --stat` + git 명령(`add`·`commit`·`push`)만
- 시작 = `git pull` / 종료 = 반드시 `push` (미완이어도)
- **두 기기에서 같은 배치를 하지 않는다.** 커밋은 한 기기에서만
- frontmatter 값에 콜론 금지 · 폴더는 **`Zotero/`**(대문자) · `review-*`는 `progress/`, action-items는 `Analysis/`
- 커밋 메시지는 **완성 문장으로** 명령 블록에 넣는다(`...`로 남으면 이력에 그대로 들어간다)

### 파일 종류

| 종류 | 성격 | 규칙 |
|---|---|---|
| `action-items-*` | **휘발성** | 새 파일은 자립. 미결은 링크가 아니라 **본문 이관**. 이전 파일은 종료 표기 후 아카이브 |
| `review-*` | **시점 기록** | 누적. **같은 날짜 안에서는 절 추가 가능, 날짜가 바뀌면 새 파일** |
| `progress/HANDOFF.md` | **단일 파일** | 덮어쓴다. 날짜별로 늘리지 않는다 |
| `Analysis/`·`Writing/` | **영속** | 결론이 사는 곳 |
