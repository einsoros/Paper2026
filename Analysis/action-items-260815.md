### A0-2. 「방법론적 회고」 절차 — 결과가 예측과 다를 때

**기각을 실패로 두지 않는다.** 논의 장을 3단으로 구성한다.

```
① 무엇을 설명하려 했는가
② 이 방법론으로는 그 설명을 충분히 검증하거나 담을 수 없다
③ 후속으로 어떤 방법적 재설계 · 시나리오 구성이 필요한가
```

> ⚠️ 프로포절 §03 또는 §07에 미리 써둔다. *"결과가 예상과 다르면 무엇을 알게 되나"*는 심사에서 나올 질문.

#### ⬜ [08-15 추가] H3 부분매개 · 직접효과 잔존 시의 해석 방침

현재 A0-2는 **H4 기각 시나리오**만 다룬다. H3도 같은 구조가 필요하다.


## ★ A. G1 — IV 신규 구성개념 방어 3단 논거 ⬜

- **Done =** 한 페이지 정리 → `Writing/proposal-draft-260813.md`에 삽입

**교수님 원칙**: 임의로 변수를 구성하면 신뢰성을 인정받지 못하며, **통계적 절차에 의해 검증된 기존 학술 변수**를 활용해야 한다.

### ⚠️ 먼저 구분할 것 — 방어의 핵

| | 지적 내용 |
|---|---|
| 김효현 숙달경험 | *"사실상 근무 경력에 가깝다"* → **기존 변수의 열등한 대체물** |
| 본 연구 귀속 모호성 | 기존 변수로 잡히지 않는 현상 → **신규 영역** |

전자는 *"있는 걸 왜 새로 만드나"*, 후자는 *"없는 걸 만들어도 되나"*. **답이 다르다.**

### ★ 먼저 말할 것 — 방어 범위를 좁힌다

> **완전한 신규는 IV 하나다.** DV(Colquitt 2001)·MOD(Erdogan 2002)는 기존 학술 변수이고, MV는 Rizzo(1970) 정의 (1)에 뿌리가 있다.

### 답변 3단

| # | 논거 | 재료 위치 |
|---|---|---|
| **①** | **왜 기존 변수로 안 되는가** | `construct-definition` §I·§II `What It Is Not` — 비교 개념 6개와의 차별. 특히 **사전(ex-ante) vs 사후(ex-post)** |
| **②** | **척도 개발 절차를 밟았는가** | MacKenzie et al.(2011)·Heggestad et al.(2019). **08-04~08-13 작업이 정확히 이것** |
| **③** | **이론적 뿌리가 있는가** | IV = Weiner(1985) / MV = **Rizzo(1970) 정의 (1)** — 요인분석에서 탈락해 미측정으로 남은 구성요소 (items 8·16·24·30, p.160·162) |

**형식** — `proposal-guide` §05 패턴대로 경로별 이론 배정 표 + 3단을 한 슬라이드로. Appendix에 `What It Is Not` 표 전문.

### 현행 4문항의 문제 3건

```
1 | 이 조직은 AI 활용 성과가 평가에 [어떻게 반영]되는지 명확히 설명한다
2 | 이 조직은 AI 활용 성과평가에 적용되는 [기준을 일관되게] 제시한다
3 | 이 조직은 AI 활용 여부가 성과평가에서 [어떻게 고려]되는지 명확한 절차를 제공한다
4 | 이 조직의 AI 활용 성과평가 절차는 구성원이 이해할 수 있도록 안내된다
```

| # | 문제 |
|---|---|
| 1 | **2번이 DV1과 「기준·일관」 어휘를 공유** — 주어(조직 vs 절차)로만 갈려 H4 상호작용항 해석에 부담 |
| 2 | **1·3번의 「어떻게」** — MV에서는 금지 어휘. MV와 나란히 놓았을 때 층위 점검 필요 |
| 3 | 1·3번이 거의 같은 내용 → 과소대표 |

### ★ 선행 결정 2건 — 문항 작성 전

**① 「AI 활용 성과평가」 표현이 연구 범위와 어긋난다 ★**

```
✅ 본 연구 : AI와 협업해 만든 성과를 평가한다   (평가 대상에 AI가 개입)
❌ 다른 것 : AI를 활용해서 평가한다            (평가 주체가 AI)
```

**② 영역 구분** — Erdogan(2002) 원전 확인 → 없으면 단일 차원(B안)

> ⚠️ **DV와의 판별이 핵심.** 둘 다 과정 층위이므로 **주체(조직 vs 나→시스템)**와 **양상(명확성 vs 규범적 공정성)**으로 갈라야 한다.

## E. 파일럿 설계 ⬜ (프로포절 후)

**「생략 불가」** — 측정·조작 둘 다 자체 증명해야 한다.

**확인 6항목**

2. 「귀속 모호」에서 MC가 충분히 높은가 — 양방향 실패 가능
3. 「귀속 명확」에서 충분히 낮은가
4. 조건 간 AI 사용량 지각 차이가 없는가

6. 「추가 검토 없이」가 태만으로 읽히지 않는가

## 작업 원칙

- **정의문 → 문항** 순서. 단 역방향도 있다 (문항 확정 후 정의문 공백이 드러난 사례)
- 정의문·구성개념이 바뀌면 **전수 grep**. 범위에 `Analysis/`뿐 아니라 `Experiments/`·`Methodology/`·`Writing/` 포함
- 문항·정의문은 본인이 작성, Claude는 3축 좌표와 관문 6개로 검증
- 파일·절을 명시하지 않은 지적은 확인 대상이 아니다
- 시작 = `git pull` / 종료 = 반드시 `push` (미완이어도)
